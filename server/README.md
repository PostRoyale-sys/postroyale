# PostRoyale — сервер матчмейкинга

`mm.py` — очередь Online- и Ranked-матчей и ретранслятор матча по WebSocket; `rp.py` — аккаунты, допуск в Ranked
по посту в X и RP (SQLite в `DB_PATH`, на VPS — том `/opt/postroyale-mm/data`). Только стандартная библиотека Python 3.10+.

**RP и допуск — только на сервере:**
- аккаунт — гостевой токен сессии (у клиента), привязка кошелька Solana (подпись nonce, ed25519) переносит его на другие устройства;
- пост для допуска должен содержать #PostRoyale и личный код игрока (`PR-XXXXXX`); один пост и один X-аккаунт — один игрок;
  перед каждым рейтинговым матчем пост перепроверяется (раз в 30 мин), удалён — допуск снят;
- Ranked идёт только через этот сервер: RP начисляет сервер по событиям матча (смерть игрока сообщает сам игрок —
  убийце +10; ботов — не больше, чем их в матче; сундуков ≤ 12; выживание — по часам сервера; победа — только когда
  все остальные мертвы и прошло ≥ 90 с, или дожил до конца раунда); лимит `RP_DAILY` (800) в сутки; журнал — таблица `ledger`;
- одно место в рейтинге на аккаунт (вторая вкладка — `busy`); магазин и золотой кейс списывают RP на сервере.
- Предел: игру по-прежнему считают клиенты, поэтому читер-хост ботов может приписать себе ботов и победу над ними —
  но не больше, чем честно возможно за матч, и не больше суточного лимита. Полная защита — только серверная симуляция боя.

**Как работает очередь** (одно общее лобби на `MM_CAP` мест):
- сразу `MM_BOTS0` ботов (13), дальше +1 бот каждые `MM_STEP` с (3), пока лобби не заполнится — тогда матч стартует (один игрок — ~18 с);
- набралось `MM_CAP` живых — старт сразу; живой игрок, пришедший в лобби, занимает место бота.

После старта сервер пересылает действия игры (`pose`, `shot`, `hit`, …) всем в матче или одному адресату. Логику
по-прежнему считают клиенты: ботов — «хост» (наименьший id среди игроков с открытой вкладкой). Протокол — в шапке `mm.py`.

## Локально

```sh
python3 server/mm.py                 # ws://127.0.0.1:8770 (MM_STEP=1 — быстрее для тестов)
python3 serve.py                     # игра: http://127.0.0.1:8766 — Online сам ходит на ws://127.0.0.1:8770
```
Два окна браузера → в обоих Casual · 🌐 Online · Play → оба окажутся в одном матче. `GET /health` — очередь и матчи.
Другой адрес сервера для клиента — параметр `?mm=wss://…`.

## На сервере (VPS 193.233.233.118, рядом с KoL'SScan)

```sh
rsync -a server/ kolsscan:/opt/postroyale-mm/
ssh kolsscan 'cd /opt/postroyale-mm && docker build -t postroyale-mm . && \
  docker run -d --name postroyale-mm --restart unless-stopped -p 127.0.0.1:8793:8770 -v /opt/postroyale-mm/data:/data postroyale-mm'
```
Caddy (`/etc/caddy/Caddyfile`), WebSocket проксируется сам:
```
mm.postroyale.xyz, postroyale-mm.193-233-233-118.sslip.io {
    reverse_proxy 127.0.0.1:8793
}
```
Адреса в клиенте — `MM_URLS` в `mm.js` (сначала sslip.io, затем `wss://mm.postroyale.xyz` — нужна A-запись `mm` → 193.233.233.118 в DNS Vercel). Нагрузка: на 2 ядра / 4 ГБ — сотни игроков онлайн (сервер только пересылает
сообщения); 20 игроков в матче ≈ 0.3–0.5 МБ/с исходящего трафика на матч.
